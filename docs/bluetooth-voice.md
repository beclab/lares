# 用蓝牙设备跟 Lares 说话、听回答

在 Olares 本机的浏览器里打开 Lares，把一只带麦克风的蓝牙音箱连上。之后可以用它说话，Lares 把话说成文字；这一轮回答完成后，只把最终回答从同一只音箱读出来。

浏览器要开在 Olares 自己的桌面上（HDMI 显示器前）。从另一台电脑或手机打开页面时，麦克风和喇叭仍是那台电脑或手机的，不会走到 Olares 上的蓝牙设备。

## 设备和机器

音箱必须同时能听和说，也就是经典蓝牙里的通话（HFP）和立体声播放（A2DP）都要有。只负责放声、麦克风归它自己的音箱（例如小爱）不行：Olares 听不到你说的话。只支持 LE Audio、不支持经典蓝牙通话的新耳机也不要选，当前系统的 BlueZ 接不住。

机器上需要：

- 蓝牙硬件可用，桌面用户 `olares` 已登录。用 HDMI 打开 Olares 时就是这个状态。
- 安装的是带蓝牙安装步骤的 Lares。安装时会自动补齐宿主机环境。没有蓝牙硬件时 Lares 仍会装上，只是语音设置里会提示蓝牙还没就绪。

还没有这段安装步骤的旧镜像，安装时会跳过蓝牙准备。那种机器即使用界面去扫描，也会提示蓝牙还没就绪。

## 安装时自动准备的内容

不需要再手工装插件或写系统服务。Lares 安装（以及之后 Pod 重新创建）时会在宿主机上检查并补上：

| 缺什么 | 装上之后做什么 |
| --- | --- |
| `bluez` | 提供蓝牙服务和 `bluetoothctl` |
| `python3` | 运行蓝牙代理 |
| `libspa-0.2-bluetooth` | 让系统出现蓝牙麦克风和喇叭；刚装上时会重启桌面的 WirePlumber |
| 宽频语音服务 | 开机后打开 16 kHz 通话。这个开关系统不会记住，关着时录音是全静音 |
| 蓝牙代理服务 | 一直在后台等 Lares 的扫描、连接、录音和播放 |

这几步失败不会拦住 Lares 启动。失败时到语音设置里会看到「这台机器的蓝牙还没就绪」。

## 第一次使用

1. 坐在 Olares 的显示器前，用本机浏览器打开 Lares。
2. 打开 **语音设置**。
3. 看顶部状态。
   - 显示「识别就绪」和模型名：语音识别已经可用。
   - 显示「还没有语音识别模型」：点语音识别那一行的 **安装**。装的是识别应用 Parakeet。页面提示已开始安装后，等模型下载完，再点右上角 **刷新**，直到变成「识别就绪」。
4. 要听回答，打开 **开启语音播报**。没有播报模型时，点语音播报那一行的 **安装**（Kokoro），下载完再刷新。播报关掉时，文字回答正常，但不会出声。
5. 识别语言可以保持「自动检测」。指定语言会更稳。目前验证过的说法是英文短句。
6. 把音箱进入配对（等待连接）状态，放到机器旁边。
7. 在 **蓝牙设备** 一行点 **扫描**。扫描要几秒，按钮会变成「扫描中…」。
8. 列表里出现这只音箱后点 **连接**。连上后这一行显示 **已连接**。

连接做完这几件事，而不只是配对：

- 确认宽频语音是开的。
- 把音箱收成麦克风，并等系统里出现它的录音口。
- 录音口没出现时，会断开再连一次。仍然没有，连接失败，页面提示确认设备还在等待连接。

扫描结果为空时，页面写「附近没有正在等待连接的设备」。让音箱重新进入配对，再扫一次。

## 说话

输入框右侧是麦克风按钮。输入框正在生成回答时，按钮不可用。

1. 确认音箱麦克风没有静音。我们用过的那只音箱，蓝灯亮着是静音，蓝灯熄灭才在录音。别的型号看它自己的静音指示。
2. 点麦克风。按钮先显示「正在连接蓝牙麦克风…」。音箱如果还停在立体声播放，这一步把它切回通话配置，麦克风口一出现就开始录。已经在通话配置上就直接开始。麦克风口没出现时停在这里，提示「蓝牙麦克风还没连上」，这次不会开始录。
3. 按钮变成「点击结束录音」后开始说。说完再点一次。
4. 按钮显示「转写中…」，识别出的文字写入输入框。
5. 文字确认后照常发送。

录音太短、没有检测到声音、或音频无法识别时，输入框不会写入文字，按钮上会短时间显示原因。

浏览器交出的录音会先收成 16 kHz、单声道、16 bit 的 WAV，再送给识别模型。不要改回直接上传浏览器原来的 48 kHz 录音，那种文件模型听不准。

## 听回答

语音播报打开后，只朗读这一轮的最终回答。思考过程、工具调用，以及调用工具之前说的话，都不读。

回答全部完成后才会出声，不会边生成边读。出声前，系统把同一只音箱从通话配置改成立体声播放，浏览器再把声音放出来。所以听回答和用麦克风说话不会同时发生。下一轮再点麦克风时，会切回通话配置。

听不到声音时，先看语音播报是不是开着，以及这一轮是不是已经结束。播报开着但音箱仍没有声音，再按下面的检查看播放有没有切过去。

## 出了问题先看页面上的这句话

| 页面提示 | 含义 | 怎么处理 |
| --- | --- | --- |
| 这台机器的蓝牙还没就绪 | 宿主机还没有可用的蓝牙音频，或蓝牙代理没在跑 | 确认装的是带蓝牙安装步骤的版本，然后重启一次 Lares，让安装步骤再跑一遍。机器没有蓝牙硬件时，这条会一直在 |
| 附近没有正在等待连接的设备 | 扫描这几秒里没有设备在广播 | 音箱进入配对后再扫描 |
| 连接失败，请确认设备仍在等待连接 | 配对上了，但没有变成可用的麦克风 | 保持配对状态再连一次。仍失败就看下面的宿主机检查 |
| 蓝牙麦克风还没连上，请重试 | 点录音时通话麦克风没有出现 | 确认音箱还连着，取消静音（验证过的那只：蓝灯熄灭）后再点麦克风 |
| 还没有语音识别模型 | Router 里没有识别模型 | 在语音设置里安装，下载完刷新 |
| 麦克风权限被拒绝 | 本机浏览器没有把麦克风权给这个页面 | 在浏览器里允许这个站点使用麦克风。页面必须开在 Olares 本机 |
| 没有检测到声音 / 音频无法识别 | 录到了，但不是可用的语音 | 靠近音箱、取消静音，说一句完整的话再录 |

## 宿主机确认

只在页面提示蓝牙没就绪、或连接一直失败时做。在 Olares 本机上执行。

蓝牙代理和宽频语音都应是活动的：

```sh
systemctl is-active bluetooth bluetooth-wideband-speech bluetooth-voice-ready
```

三个都应打印 `active`。宽频语音是一次性服务，成功后也会保持 `active`。

音频插件应已安装：

```sh
dpkg -s libspa-0.2-bluetooth
```

桌面用户的音频会话应在。把 `1001` 换成 `id -u olares` 的结果：

```sh
id -u olares
ls /run/user/1001/pipewire-0
```

`pipewire-0` 不存在说明桌面用户还没登录，蓝牙麦克风和喇叭都不会出现。用 HDMI 登录 Olares 后再试。

连上并点过一次麦克风之后，通话配置应是 `headset-head-unit-msbc`，默认输入是 `bluez_input.` 开头的那一路。听回答时，默认输出会暂时变成 `bluez_output.` 开头、且不是通话编码的那一路。
